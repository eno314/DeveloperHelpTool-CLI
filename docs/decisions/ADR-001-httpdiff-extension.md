# ADR-001: CLI Option Extension for httpdiff

## Status
Proposed

## Date
2026-07-03

## Context
現在の `httpdiff` サブコマンドは GET リクエストと JSON レスポンスのみを想定しており、以下の機能が不足しています：
1. POST などの GET 以外の HTTP メソッドのサポート
2. 認証トークンやカスタムの `Content-Type` を付与するためのリクエストヘッダーの指定（複数指定可）
3. POST リクエスト時に送信するリクエストボディの指定（直接指定およびファイルからの読み込み）
4. JSON 以外のプレーンテキスト（XML、HTML等）のレスポンス比較

このコマンドラインツールは軽量かつ単一バイナリで動作し、追加の外部依存関係を極力抑える設計方針となっています。また、リファクタリング後のデグレーション検知やシステム移行時の新旧比較が主目的であるため、CLI としての手軽さと再利用性を両立させる必要があります。

## Decision
Go標準ライブラリの `flag` パッケージを用いた既存のコマンドライン構造を維持しつつ、CLI オプションを拡張して要件を満たします。

具体的には以下の設計決定を行います：

1. **`flag.Value` インターフェースによる複数ヘッダーのパース**
   `flag` パッケージはデフォルトで「同一フラグの複数回指定（例: `-header "A: B" -header "C: D"`）」に対応していません。これに対応するため、`string` のスライスをラップし `flag.Value` インターフェースを満たすカスタム型 `headersValue` を `src/features/httpdiff.go` 内に実装します。

2. **新規フラグの追加**
   - `-method` (文字列, デフォルト: `"GET"`): 大文字・小文字を区別せず HTTP メソッドを指定。
   - `-body` (文字列, デフォルト: `""`): リクエストボディの文字列。
   - `-body-file` (文字列, デフォルト: `""`): リクエストボディが記述されたファイルのパス。
   - `-header` (複数指定可, デフォルト: 空): `Name: Value` 形式のカスタムヘッダー。

3. **リクエストボディ指定の排他制御**
   `-body` と `-body-file` が同時に指定された場合はエラーを出力して実行を中断します。

4. **プレーンテキストの直接比較**
   XML/HTML のフォーマット差異を無視する（セマンティックな）比較は第一フェーズでは見送り、`github.com/google/go-cmp/cmp` を用いたレスポンスボディの純粋なプレーンテキスト（文字列）としての差分比較を行います。

## Alternatives Considered

### 1. Cobra や CLI フレームワークの導入
- **利点**: スライス型フラグ（`StringSlice`）が組み込みでサポートされており、コマンドライン構造を整理しやすい。
- **欠点**: プロジェクト全体の CLI 設計を刷新する必要があり、標準 `flag` パッケージで完結している現状に対して過剰（オーバーキル）です。
- **却下理由**: 既存のシンプルなコードベースを維持し、依存ライブラリを増やさないために、`flag.Value` によるカスタム実装を選択しました。

### 2. 設定ファイル（YAML/JSON）駆動への完全移行
- **利点**: 複雑なヘッダーや巨大なリクエストボディを毎回 CLI に手入力する必要がなくなります。
- **欠点**: ワンショットでさっと差分を調べたい場合の CLI の手軽さが失われます。
- **却下理由**: まず手軽に実行できる CLI オプションを第一歩とし、将来的にバッチ実行や複雑な定義が必要になった場合に設定ファイルをサポートする方が段階的な導入として適切であるため。今回は CLI オプションによる拡張を選択しました。

## Consequences
- ユーザーは POST API や、認証トークンが必要な API に対しても `httpdiff` を使用した差分検証が可能になります。
- `-body-file` により、大きな JSON ペイロードなどもファイル経由で安全かつ綺麗に送信できます。
- XML や HTML のインデントや改行コードに違いがある場合、それらもすべて「差分（ノイズ）」として検出されるため、ユーザー側でのフィルタリングや事前整形が必要になる場合があります（これは将来的に必要に応じてオプショナルな整形機能として拡張可能です）。
- `httpdiff` サブコマンド内のリクエスト実行部 (`doRequest` などのヘルパー関数) が少し複雑化しますが、すべて Go 標準ライブラリの範囲内で完結します。
